# Source-backed desktop parity inventory

Current-source refresh: **2026-10-10**, macOS arm64, source/headless review only.
The earlier foundation inventory is historical. This inventory traces actual Mac
behavior into Windows receiving entries and identifies remaining work; it does
not approve a release or replace task evidence/W34 observations.

Accepted support remains **Windows 10 22H2/build 19045 native x64 and Windows 11
native x64**, qualified physical DirectML model inference, one shared Chrome
extension and a **no-admin worker only in the logged-in Windows session**.
No ARM/x86/emulation, service/CPU inference fallback or automatic cloud fallback.

## Source and proof labels

**Source present** means the named receiving UI/entry reaches actual domain and
authority source. The linked task matrices record meaningful portable tests;
native/device/live behavior is still W34. A control or fake port alone does not
close a requirement. **Return pending** identifies concrete moving source below.
**Release review/input pending** identifies approved artifacts, availability and
signing/license/dependency decisions; no invented feed or installer fills that gap.

Every desktop action below enters [closed contracts](../src/shared/contracts.ts),
[preload](../src/preload/index.ts), [current-frame ingress](../src/main/desktop-ipc.ts)
and [Main](../src/main/main.ts). Chrome uses the separately validated
[browser host](../src/agent/browser-host.ts) / [gateway](../src/main/browser/service.ts).
Window, account UID/generation, Windows SID/logon, approved fleet machine and
physical GPU ownership are distinct authorities, rechecked after asynchronous work.
