# Responsive Android identity and localization

Use Android as the source of truth, not the dashboard visual theme.
Confirmed tokens: background `#101115`, surface `#191B21`, default accent
`#FF814A`, main foreground `#F2F0F5`. Android uses Noto Sans Arabic, rounded
12/20/28 dp shapes, waveform artwork, and contrast-adjusted accents. Translate
its full token system to CSS variables, including readable on-accent colors,
spacing, typography, focus, error and disabled states. Verify font redistribution
and reuse repository assets only where suitable.

Phone layout: compact navigation and accessible persistent mini-player.
Tablet/desktop: sidebar and wider content layouts with a persistent player;
use space effectively instead of stretching a phone screenshot. Suggested test
widths are 360, 390, 768, 1024, and 1440 CSS pixels. Use content-driven breakpoints.

Required routes/journeys (final URLs are an implementation choice):

- Auth gate, login, registration, reset password, verification, provider errors.
- Home with URL/audio intake, review and rights confirmation, trim selection.
- Jobs/history, source import progress, job details and completed result details.
- Library search/filter/sort and relevant favorite/hide/restore actions.
- Full player, mini-player, queue and the controls actually present on Android.
- Settings, language/accent, usage, account, linked providers, devices,
  sign-out, sign-out everywhere, account deletion and recovery.

Build the inventory before declaring parity. Preserve explicit confirmations for
user-destructive actions. Support browser back/forward, deep links and reload,
keyboard navigation, visible focus, accessible labels, dialogs with focus return,
reduced motion, long titles and 200% zoom. Playback must survive route changes.

Provide complete English and Arabic catalogs, correct document `lang`/`dir`,
logical CSS properties, localized numbers/dates/plurals, and bidi-safe URLs,
filenames and job IDs. Do not mirror universal playback symbols indiscriminately.
Do not embed user-facing English strings in components. Preserve language/accent
preference without exposing one user's private state to the next user.

Include loading, empty, failed, unauthorized, expired session, suspended account,
quota exhausted, unavailable processing, stale signed URL, and offline/network
states. Disabled actions must explain the actual server-provided restriction.
Do not hardcode the README's historical processing-unavailable claim.
