## Android-to-iOS parity reconciliation (2026-09-27)

The production iOS graph now follows Android's three primary destinations rather than exposing Processing as a fourth tab. Platform-native provider, picker, sharing, notification and update behavior remains intentionally native.

| Android product area                                                            | iOS implementation                                                                                                                                                                                                           | Current local evidence                                                                |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Home: compact brand header, link/file intake, live recent jobs                  | `HomeView` keeps both reviewed intake paths and embeds the shared realtime task list; full processing history/details open from Home                                                                                         | Compiles for the authorized simulator; fixture UI smoke passes                        |
| Library: search, newest/title sort, starred, downloaded/not-downloaded, removed | `LibraryView` adds owner-scoped preferences, private-cache detection, equivalent filters, explicit download/progress, play and details                                                                                       | Cache state comes from validated private artifacts; dedicated fixture journey passes  |
| Persistent mini/full player                                                     | `MiniPlayerView`, `PlayerView`, `ProcessingModel` and `AudioPlayer` provide original/voice, queue editing, previous/next, seek, shuffle, repeat, auto-next, speed, volume, favorite, info, Save Original and remote controls | Dedicated fixture journey covers download, favorite redraw, Save Original and details |
| Settings: account, usage, accent, language, help/legal/about                    | `SettingsView` retains account/appearance/language and adds usage, preset/custom hex accent, support, privacy and terms; obsolete future placeholder removed                                                                 | Accent validation/persistence and control clamping have unit coverage                 |
| Dark creative visual language and accessibility                                 | `Design.swift` uses Android's `#101115`/`#191B21` surfaces and `#FF814A` default accent; 44-point controls, Dynamic Type and EN/AR RTL remain                                                                                | Source formatted; 156 unit tests and all 11 simulator UI tests pass                   |

Web uses the same three primary destinations and compact Home hierarchy. `/jobs` and job-detail routes remain reachable from recent activity and deep links so existing URLs stay backward-compatible. Its online-only Library deliberately omits Android offline filters, as approved in the browser scope, while exposing a normal browser download action. The web player exposes original/voice selection, editable queue, auto-next, repeat-all/repeat-one, favorite, details and Save Original without reintroducing polling.
