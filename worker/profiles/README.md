# GPU runtime candidates

`macos-arm64-coreml.candidate.json` and its exact hash-bound lock are an isolated
Kim Vocal 2 preparation recipe, **not a qualified release**. The product has no
qualified catalog entries. Selection excludes every candidate; native service,
boot, reference-quality and media-capacity approval remains required.

The minimal dependency set intentionally excludes audio-separator, PyTorch,
diffq and other model families. Its sole numerical implementation remains
`musicmute_worker/separation.py`; it follows pinned audio-separator v0.47.0 MDX
defaults (256 frames, 1024 hop, 7680 FFT, .25 overlap, batch one, denoise off).
It supports only the exact recorded Kim Vocal 2 model and stereo 44100 Hz input.

The two-second fixture is generated locally using the exact integer algorithm in
`profiles.smoke_fixture`; it is not a vocal-quality reference. The four-GiB host
RAM and 120-second timeout are conservative diagnostic caps, not measured media
capacity or allocation reservations. Apple GPU memory is reported as unknown,
separately from total unified RAM and process host RSS.

`Profile.load(path, expected_sha256)` requires the digest already authenticated by
W03's release verifier. `prepare_runtime` verifies and unpacks the Python archive,
canonicalizes its safe relative aliases to regular files, installs only verified
wheels offline in a private environment, checks exact installed versions, verifies
FFmpeg, FFprobe and the model, and leaves an unsuccessful staging directory unactivated.
The caller owns cleanup/retry of its isolated staging directory. Existing cached
assets are always rehashed; corrupted cache entries are refused, never trusted.

The Jellyfin FFmpeg/FFprobe 7.1.4 pair is a reproducible **local diagnostic candidate**, not a
shipping approval. Its portable archive lacks the binary's full GPL source
and notices package. H01 must provide a current reviewed native FFmpeg build and
notices before publishing. Python/native/FFmpeg/model artifact provenance and
redistribution limits are recorded in `evidence/portable-runtime-assets.md` and
`evidence/model-artifact.md`. No model or binary payload is included here.

Admission compares the entire prepared runtime inventory, including interpreter
link targets, modes, bytecode and all added files. Only `work/` contents may change;
links into that directory are refused. Post-preparation Python launches use `-I -B`
to isolate imports and prevent generated bytecode from changing the inventory.
Both media tools are explicit verified paths throughout worker media processing.

Windows/Linux/Intel Mac candidates remain unavailable: no lock or hardware
support is fabricated for them. New native recipes must supply their own verified
interpreter packaging and GPU execution evidence. GPU options are exact and
allowlisted; CPU, AUTO and heterogeneous CPU fallback configurations are rejected.
