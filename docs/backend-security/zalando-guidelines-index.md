# Zalando RESTful API and Event Guidelines: MusicMute index

> MusicMute is in local development with no users. The maintainer accepts coordinated breaking API/client changes and requires every applicable portable MUST/MUST NOT rule to be implemented. This index separates those requirements from optional and Zalando-only rules.

## Portable MUST/MUST NOT disposition

The six groups below were the initial gap list. The coordinated local migration now has:

1. **Interface and security (100, 101, 104, 105, 116, 151, 192, 218, 219):** a versioned OpenAPI contract with 119/119 HTTP route parity, explicit audiences, authentication, permissions, schemas, examples, and errors. Its publication accompanies a future authorized deployment; the local artifact is complete.
2. **Error transport (176, 177):** RFC 9457 Problem Details with safe stable codes, request correlation, redacted 5xx detail, and updated client decoders.
3. **JSON and query naming (118, 130):** snake_case public wire properties and query names with strict legacy-key rejection, plus coordinated first-party adapters and fixtures.
4. **Resource URLs (115, 141, 138, 134, 129, 136, 142, 143):** no URL version prefix or action aliases; resource paths and callers migrated together. Rule 114 is conditional on coexistence of incompatible representations, which this local migration does not require.
5. **Wire semantics (148, 149, 154, 220, 243, 153, 162, 227, 159):** route methods/statuses documented, scalar query serialization defined, immediate 429 limits provide `Retry-After`, sensitive responses use `no-store`, and collections use bounded pagination.
6. **Data and client evolution (171, 169, 123, 174, 108, 110, 111, 122, 106):** number/time formats, object responses, stable field meanings, boolean semantics, and additive response tolerance are in the contract and client tests. The breaking change is coordinated only in this local worktree; deployed compatibility requires a separate release decision.

See [implementation status](implementation-status.md) for command evidence and limits of local verification.

## Interpretation notes

- Rules 125, 126, and 128 are legacy aliases in the source, not three additional requirements. Their paired rows link both source anchors.
- Zalando’s internal registry, naming, hostname, tracing header, and Nakadi event-type rules require MusicMute-specific alternatives rather than literal copying. Published-event rules become applicable if a consumer-facing event interface is introduced.
- Conditional MUST rules become required when their trigger exists; for example, media type versioning under rule 114 if incompatible versions must coexist, and 207 bulk responses under rule 152 if a bulk endpoint is introduced.
