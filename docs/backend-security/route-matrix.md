# Backend route and security matrix

Source inventory for the Nest HTTP application in `backend/src/app.module.ts` and the direct HTTP upgrade in `backend/src/worker-hints/worker-hint.service.ts`. There are **119 controller HTTP handlers** plus **one WebSocket upgrade path**. Paths in the tables are root-mounted. The two public HTML pages are called out separately. This records source behavior; a linked test suite is a place to verify a contract, not a claim that every listed route has an individual passing test.

## Shared controls and notation

| Code              | Actual policy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P                 | Public: `@Public()` skips Firebase authentication.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| U                 | Current active mobile account: Firebase bearer signature/session checks, local profile, session revocation and account status. `U0` permits an unprovisioned identity only for session bootstrap; `UR` permits a deleting account for recovery; `UD` permits deletion retry. Owner IDs for account/job/device operations come from the authenticated account, never the request body.                                                                                                                                                                                             |
| A(`permission`)   | Verified Google Firebase identity plus current active admin record, matching normalized verified email and role permission. `A` alone means admin admission with no specific permission. `F` adds recent Firebase authentication (default maximum age 300 seconds). Admin operation IDs, expected revisions and reason fields are stated under input bounds.                                                                                                                                                                                                                      |
| W-E / W-I / W-M   | Worker enrollment invitation, installation session or machine credential. `WorkerAuthGuard` looks up the SHA-256 digest; enrollment and installation credentials expire, machine credentials must be active unless a route explicitly allows revoked machines. Handler services also check the principal against path IDs, session/incarnation and attempt ownership.                                                                                                                                                                                                             |
| G                 | Redis global IP throttlers: default 60 requests per 60 seconds plus overall 600 per 60 seconds, configured by `RATE_LIMIT`, `RATE_TTL_MS`, `RATE_IP_CEILING_PER_MINUTE`. Liveness skips both; two job reads skip the default bucket but retain overall. JSON body maximum defaults to 64 KiB. Global DTO validation strips/rejects unknown properties and transforms typed DTOs; plain `unknown`/`Record` inputs rely on explicit service validation.                                                                                                                             |
| Ux                | In addition to G, private UID limit default 120/minute. `profile`: UID 5/minute and IP 10/minute; `device`: UID 10/minute; `logout`: UID 3/hour. `processing-*` and account deletion/recovery operations have scoped account/IP/endpoint/service Redis budgets in `AuthGuard` (see below). Processing reads omit the general private UID bucket.                                                                                                                                                                                                                                  |
| Ax                | In addition to G and Ux, admin Redis budgets per UID, IP, endpoint and service. Default UID classes: read 120/minute, write 30/minute, media 20/minute, sensitive 5/minute, export 5/hour; admin IP 60/minute, endpoint 300/minute, service 1,000/minute. GET defaults to read, other methods to write unless `@LimitAdmin` overrides.                                                                                                                                                                                                                                            |
| Wx                | Worker HTTP routes retain the global 600/IP/minute ceiling and skip the shared 60/IP/minute default. Before credential lookup, atomic Redis budgets apply at 300/IP/minute and 3,000/service/minute, including invalid credentials. After lookup, budgets apply by principal kind (machine 300, installation 120, enrollment 20 per minute), class (standard 120, poll 240, transfer 30, telemetry 30 per minute), endpoint (1,200/minute) and service (3,000/minute). Classes are marked in each row; all values except the global IP ceiling are configured by `WORKER_*` keys. |
| B                 | Bound in a DTO, explicit query parser, service or policy; exact salient bound is written in the row. `empty` means `EmptyBodyPipe` or explicit empty-object check. `none` means no query/body parameter. All applicable requests retain the global body cap.                                                                                                                                                                                                                                                                                                                      |
| D / S / M / E / C | Relative abuse/cost focus: MongoDB/Redis work; S3 grants or object checks; email; CSV/export; worker command or compute. A route can have several.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| M / A / W / P     | Consumer: native mobile app, admin dashboard/operator, worker runtime, public browser/health client.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| I / R             | Status: `I` is implemented in source; `R` is an identified risk needing separate review. These labels do not establish production deployment or live-provider proof.                                                                                                                                                                                                                                                                                                                                                                                                              |

`processing-read` defaults to 60/account/minute; `processing-create` and `processing-retry` to 30/account/minute; grant, confirmation, download and mutation classes to 60/account/minute. Account deletion defaults to 3/account/hour and recovery to 60/account/hour. These classes also use defaults of 120/IP/minute, 600/endpoint/minute and 2,000/service/minute. The IP/endpoint/service windows are 60 seconds, including for account deletion/recovery. Mail has separate recipient/IP/UID/day reservations.

## Owned audio and transfer routes

These handlers resolve the job by authenticated account ID. Creation, upload renewal/confirmation and retry also require the processing access policy (verified email and minimum app build). The current unavailable-processing gate can return `PROCESSING_UNAVAILABLE` before new costly work. Result grants use stored immutable object metadata; upload confirmation verifies exact object bytes/checksum/version. The account policy further bounds 20-minute/50,000,000-byte prepared input, daily/monthly grants and bytes, queue slots, retries, downloads and retention. The route table records the request boundary; those durable policy checks are in the service layer.

## WebSocket and non-controller boundary

| Method and path                             | Auth / ownership                                                                  | Validation and collection or payload bound                                                                                                               | Abuse / cost           | Rate                                                                                                                 | Consumer; tests; status                                                        |
| ------------------------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `GET /worker/hints/socket` **HTTP upgrade** | one-use Redis ticket minted for W-M machine, TTL 30 seconds; no bearer on upgrade | ticket in exact WebSocket subprotocol, no query/Origin; receive-only, 1,024-byte max payload, compression off; max 2 sockets/machine and 1-hour lifetime | D, connection capacity | direct `httpServer.on('upgrade')`, outside Nest guards; Redis limits 120/IP, 3,000/service and 20/machine per minute | W; `worker-hint.service.spec.ts`; focused unit and isolated integration passed |

The WebSocket endpoint is not a Nest controller route. Incoming client messages close the socket; hints are advisory and workers still reconcile against authenticated HTTP state. Its direct upgrade path has separate abuse controls because `ApiThrottlerGuard`, `AuthGuard`, the JSON parser, CORS and the exception filter do not run there. The ticket is carried in the WebSocket subprotocol rather than a URL query. Unknown upgrade paths receive a 404 rejection and socket close.

## Review findings and validation boundary

1. **Public account deletion disclosure**: the first inventory found conflicting 15-day and three-calendar-month text. Both public pages now state the accepted 15-day recovery period; focused controller tests cover the rendered content.
2. **Worker rate and socket controls**: the first inventory found only shared per-IP worker HTTP throttling and an unbounded direct WebSocket upgrade. This branch adds principal budgets and separate upgrade/connection caps. Guard, socket, and isolated rate-limit tests cover these controls, including reverse-proxy IP handling and reconnect behavior.
3. **Unknown WebSocket upgrade path**: the first inventory found a return without a socket close for unrelated upgrade paths. A focused test covers the new 404 rejection and close.
4. **Public APK cost boundary (`R`)**: the two public APK grant routes limit issuance to 10/IP/minute and verify the current published release. Their presigned S3 download URL remains reusable until expiry (default five minutes, maximum ten). Actual download bytes and repeat fetches are outside API observation, so edge/S3 policy must carry the egress-cost control.
5. **Status**: source inventory and test locations were reviewed locally. No command here proves Firebase, Atlas, Redis, S3, email, a deployed reverse proxy, a physical device, or production behavior. Use focused e2e/integration tests and operational validation for those boundaries.
