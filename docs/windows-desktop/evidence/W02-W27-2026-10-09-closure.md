The host reads the actual sealed desktop version/build metadata; no hardcoded release build is substituted.

The [shared manifest](../../../chrome-extension/src/extension/static/manifest.json) and key remain one source/identity. [Registration](../../../windows-desktop/src/main/browser/registration.ts) derives that identity and reads only sealed approved integration resources. HKCU registration and its ownership checks are [W26](../tasks/W26-chrome-native-host-and-registration.md) source; actual registration remains W34.

[localPlatform](../../../chrome-extension/src/shared/local-platform.ts) explicitly identifies native Windows x64, build ≥19045, `windows-user`, DirectML and named pipes. ARM emulation and older Windows fail. The [runtime adapter](../../../worker/src/platform/runtime-adapter.ts) retains `legacy-service` as a separate explicit profile; the consumer does not select WinSW/SCM/LocalService solely from `win32/x64`. [browser-platform](../../../chrome-extension/src/shared/browser-platform.ts) is browser-safe and chooses local provider only from validated host platform/architecture. Static `LOCAL_WINDOWS` availability stays false; actual HELLO/cache/host readiness supplies discovery. Existing Mac `LOCAL_MACOS` and page-local intent remain compatible.

Native credentials/nonces/process/Job authority stay in [Consumer SDK](../../../worker/src/platform/windows/consumer-native.ts), [session control](../../../windows-desktop/src/main/session/control.ts), and [account bridge](../../../windows-desktop/src/main/browser/account-bridge.ts). Chrome receives only bounded provider/scope/job/check/diagnostic/media data. Neither boundary accepts browser-selected UID, bearer, GPU ordinal, raw executor or worker controls.
