are primary constraints; redistribution rights/notices must come from actual
approved inputs. The source now audits the private static dependency graph before
both package publication and fresh-stage proof. It rejects missing app-local VC
DLLs, ambient/global resolution, bundled Windows system/debug DLLs, ambiguous or
inconsistent VC copies, missing/mismatched source/notice bytes and malformed PE
tables. The sanitized source/relocated probe uses an empty PATH and private test
profile; imported modules/distributions must actually reside in the private tree.
This does not prove real DLL loading, export compatibility or dynamic loads.

native x64, official canonical Microsoft HTTPS source, reviewed compatible14.x
version, exact DLL byte lengths/SHA and a hash-bound license under
`runtime/python/licenses/msvc/`. No input package/license/binary was downloaded
or substituted on the Mac. Genuine licensed VC payload, full pinned Windows
Python/DirectML dependencies, native binaries and compiled agents are still
external release inputs. The structural fixture PEs are not runnable binaries.

from the actual engine policy `windows-user/directml/onnxruntime-1.24.4/no-cpu-v1`.
Absent/old/wrong DLL policy refuses operational reuse; signed installed metadata
selection remains separate. Current proof must come from actual signed ZIP
verification and fresh dependency audit, never a default marker or inference
result relabelling.

Large complete inventories retain every covered file. The scalable status format
uses authenticated2MiB chunks plus a bounded64KiB hash index/DPAPI marker in two
fixed slots; each slot is bounded64MiB, covering the existing100,000manifest

is no8,192-file product restriction or omitted executable/metadata/model coverage.
Runtime-only CPU status is a separate protected fingerprint receipt and does not
query a GPU/current-boot witness or require a model. Genuine sizing and measured
Windows latency remain W31/N5 prerequisites.

Before runtime mutation, the coordinator persists its fixed account
`prepare_maintenance` record and reserves intake. Accepted work drains through
actual Session snapshots; no force/blanket taskkill. Retirement requires durable
old owner removal **and exact old Session Node exit**. Native new-Session and
role launches refuse held Prepare or any existing WAL phase, including retired.
Only after Controller task + positive Setup release does settlement close its
passive connection, finish the real Gate and delete WAL; one Root adapter rebind
may follow while the helper's independent busy flag still blocks intake.
ACK/rebind failures preserve recovery, including shutdown-after-failed-rebind.
Current valid Ready is still required before any new processing role launch.

## Local measurement contract

`account/startup_measurements` contains only phase, outcome, monotonic duration,
observation timestamp, origin and optional public release/modelSHA. Allowed
phases: app-bootstrap, status-check, controller-attach, model-load,
first-inference. No SID/UID/path/video/request/credential is persisted. Engine
first-inference is the first successful actual ORT Run (usually warm-up) and is
contained within model-load time; these values must not be summed as independent
costs. Missing/failed completion never becomes a successful timing. This records
samples for W34; no startup-time promise is inferred from Mac fixture execution.
