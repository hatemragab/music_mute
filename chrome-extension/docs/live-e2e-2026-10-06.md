and cloud-selected cached playback then passed on the final build. No credentials
were deleted or Keychain access rules changed. Apple documents that authentication

## Defects found and repairs

1. **GUI startup still ran full checks.** Native runtime resolution was already
   lightweight, but `app-control` status called an inspector that hashed the
   model and downloader, recursively verified YouTube tools and executed
   readiness probes. Ordinary GUI status now checks installed metadata and
   registration only, without optional package-inventory fingerprinting.
   Prepare/update and explicit checks retain full verification.
2. **A status connection could retire immediately before START or CHECK.** The
   next helper could collide with the exiting helper's native lock. A bounded
   status handoff reuses the connected helper; the expiry-boundary repair also
   recovers only helper acquisition/HELLO after an owned idle retirement.
   START is never replayed, and genuine competing-session BUSY remains visible.
3. **Saved GUI readiness could outlive a newer explicit check.** A failed Prepare
   result could remain displayed after Check again passed. Explicit CHECK now
   refreshes the corresponding saved readiness evidence, preserving current
   component failures and clearing superseded ones without startup probes.
4. **Manual-check errors lost their safe code in native diagnostics.** The fixed
   installation-check busy/failure codes are now preserved by the bounded
   diagnostics allowlist; arbitrary error text remains excluded.
5. **Setup text implied repeated content verification.** Native copy now describes
   installed contents and verification during Prepare or Check again, matching
   the trust policy rather than claiming fresh verification before every use.

One fixture run sampled offscreen audio before its first clock tick and failed
its one-shot assertion, while playback subsequently started in the native log.
`scripts/e2e.mjs` now waits within the existing bounded test timeout for a loaded,
playing audio clock to advance; it does not bypass autoplay. The full rerun
passed all 27 checks with 187 ms maximum synthetic drift.

Primary implementation areas are `src/extension/background.ts`,
`src/companion/app-setup.ts`, `app-control.ts`, `installation-check.ts`,
`diagnostics.ts` and `macos/MusicMuteLocal.swift`, with focused regression tests.
The final npm suite covers these source changes; native Swift compiled in Swift 6
mode with warnings treated as errors during packaging. Setup copy was formatted
with `xcrun swift-format format --in-place macos/MusicMuteLocal.swift`.

## Remaining acceptance boundaries

This is a dated test on one prepared development Mac. The app is ARM64 and ad-hoc
signed. It is not notarized, and preserving the already installed runtime/model
does not prove first-time runtime transfer, clean-user Prepare, Gatekeeper
acceptance or a public release. The placeholder runtime-host limitation remains
described in [setup and updates](setup-updates.md).

The measured cloud and local playback cases do not establish physical listening
quality, full audio-track matching, every advertisement/two-tab/navigation
combination, extended offscreen playback or cross-device Library delivery. A
complete native GUI acceptance matrix remains distinct from the timed installed
IPC checks. Future YouTube guest availability remains source-dependent; the
recorded refusal is preserved rather than represented as fixed.

No commit, push, backend deployment, public publication, worker-fleet change or
real-media reset was part of this installation/test request.
